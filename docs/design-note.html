Kavach HR Assistant — Design Note

Google Apps Script web app + one Google Sheet · one LLM call per message via OpenRouter (openai/gpt-6-luna, strict JSON) · 38 automated test cases, all passing (plus a 1,355-case stress run during development: 98.3%)

1. How it decides: answer, ask, or "I don't know"

The Employee ID is looked up in the Roster tab; the model sees only that person's band, grade, role type, city, probation status and HRBP name (never phone/email, never the roster). The whole policy pack (~1,800 tokens) is in every prompt — no RAG. The model must return JSON in a fixed order: topic → category → answer_type → sections → reply, so it classifies and decides answered / partial / ask_followup / not_covered / refused before writing. Prompt rules come from traps in the pack: probation overrides band for notice; check coverage before asking (an intern asking about hotels gets "not covered", not "which city?"); ask one short question when an answer depends on missing data (city for hotel limit, band for a guest, distance for Band A flights); use the tier list literally; never compute new numbers.

Code, not the model, enforces the outcome: (1) a number guard rejects any reply containing a number not found in the pack, the profile or the employee's own words, and any section that doesn't exist → one retry with the problem stated → else a safe "I can't answer that reliably" reply; (2) a footer adds "Source: Separation §5.1" for answers, and the employee's own HRBP name + email for not_covered / partial / refused (guests get the HR Helpdesk). The model can't omit or invent the contact.

2. Sensitive messages

The model classifies, code decides. Every message gets one of six categories (distress, harassment, exit, other employee's data, prompt injection, policy); a table in code maps each to its reply, flag and alert. The model reads meaning, so idioms don't fire ("deadline is killing me", "posh hotel", "leave khatam ho gayi", "Suicide Squad dekhi"). Safety layer: first-person self-harm phrases ("want to die", "jeena nahi", "suicide karna") skip the model and always get the distress template; harassment keywords take over only if the model call fails.

  • Harassment (sexual, bullying, abuse, discrimination, retaliation) → fixed template, no AI: IC email, 3-month window (+3), confidentiality, no retaliation, HRBP support (§4.2–4.5). Severity high: Flags row + email.
  • Distress or a wellbeing concern → fixed, caring template: Mann Sahayak EAP 1800-000-4357 / email, emergency services (§6.1–6.2), HRBP; Hinglish line. A repeat message gets a short version. Severity urgent: Flags row + email.
  • Exit intent → normal answer (e.g. notice period) + Flags row for the HRBP.
  • Other employee's data / prompt injection → refusal + low-severity flag.

Templates work even if the LLM is down. One Flags row per type per chat; the HRBP view tab lists open flags by HRBP.

What could go wrong: subtle distress missed by both layers; the model misreads a borderline message (asking about POSH is answered normally, reporting it gets the template — tested both ways); a typed ID can be spoofed, so a flag could name the wrong person; the alert email contains the message excerpt — in production it should go only to the IC/HRBP.

3. Chose not to build

  • RAG / vector DB — pack fits in one prompt; retrieval only adds a way to miss the right section.
  • Real login — brief uses the ID as a stand-in. Production: Google sign-in on the company domain, email → ID.
  • Leave balances — not in the pack; the bot gives entitlement + "check PeopleHub".
  • WhatsApp/Telegram, streaming, admin UI — channel isn't scored; the Sheet is the admin UI.
  • Follow-up questionnaires and extra case types (threats, whistleblowing, grievances) — built and tested, then cut: beyond the brief, and a questionnaire can swallow the employee's next question.

5. Running cost per 1,000 questions

Measured on 32 real calls: ~3,200 input + ~76 output tokens per call; median 2.4 s. At $0.10 / $0.50 per M tokens: ≈ $0.36 uncached; with OpenAI's automatic prompt caching (99% of input cached in tests, since the pack prefix is identical) ≈ $0.07. POSH/distress keyword hits cost $0. Apps Script and Sheets: ₹0. Every Log row records tokens and cost.

6. Gaps and contradictions found in the pack

  • §1.3 "all bands get 12 days CL/SL" vs §1.5 "no other leave type applies to interns" → followed §1.5.
  • Interns have no hotel, DA, travel-mode, WFH, maternity or paternity rules → "not covered".
  • §2.2 late marks deduct EL first, but probationers can't use EL (§1.4); unclear if the 9:45 AM rule applies to Field Sales' geo-punch.
  • Delhi NCR lists only Delhi, Gurugram, Noida → Faridabad/Ghaziabad answered as Tier 2/3 + "confirm with HRBP".
  • §6.2 "a crisis helpline" has no number → bot never invents one. IC members are unnamed.
